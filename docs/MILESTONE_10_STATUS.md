## 1. Safety fixes (`rules-v10`)

| Failure class | Fix | Effect |
|---|---|---|
| Keyword stuffing | A sentence written for a keyword filter isn't evidence: a "Keywords:" label, repeated words, or a list repeating its first or last word. A labelled tool list is a lead, never direct use | Variants give Not enough information; honest short lines such as "Windows support, Mac support, printer support" still count |
| Workplace names | Only what the person did counts: "Aide, Harbor Nursing Home" is "Aide". "Manager, Accounting" names a specialty and stays whole. Working in a setting a requirement names ("Hospital experience") is Possible at most | A workplace's name no longer covers a field |
| Duration formats | One parser for yrs, yr, mos, mo, mths, combined amounts, decades, and full-width digits. "Several years" asks for time it doesn't state, so it never reaches Supported | "yrs" is held to the amount |

**Other bugs found and fixed along the way:**

| Bug | Before | Now |
|---|---|---|
| "2 years and 6 months" | Read as 6 months | 30 months |
| A month-only amount naming a technology, such as "48 months of welding" | Judged as a plain skill, ignoring the time | Held to the time |
| An instruction typed plainly into a title, field, or credential name | **Still counted as evidence on 5 paths to Supported** (found by this milestone's audit) | Never counted |
| "Administered Tableau for 300 users" | "Users" made it look like a consumer | Reads as work |

## 2. Clarification workflow

1. A result of Possible or Not enough information shows a question generated by rules.
2. "Yes, add details" only opens an empty form. It sends and saves nothing.
3. The person picks a role and says what they did. Vague answers, keyword lists, instructions, claims, wishes, and hidden characters are refused, and what they typed stays in the form.
4. The answer is saved apart from the role's own text, and the rules engine runs again. No AI service is involved.
5. **The verdict stays one of the four.** "Supported — Self-reported" is a display label over `supported`, and where the evidence came from is stored separately.
6. An answer that doesn't state the person's own work leaves the verdict alone, and the page says so.
7. Answers are listed on the analysis page and can be removed.

| Question type | Answered by |
|---|---|
| Work or a skill | Role plus a typed description |
| Credential | Name, issuer, month earned: an education entry tied to the answer |
| Degree | Qualification, institution, dates |
| Time in a non-technical field | Link to Experience, since a sentence can't add months |
| Skill level or name | Link to Skills |

**"No"** stops the question for that job, and changes no verdict or profile.

**Local AI:** it can only add a note that it also pointed at a requirement. It can't write questions or change results, and the workflow runs without it.

**"Verified" removed:** the page no longer calls results or evidence verified, including resumes and certifications. It now says "Self-reported: CareerOS hasn't independently verified it." A test scans the user-facing files for the word.

**Screenshots:** `docs/m10/`.

### Known limits

- **Answers can be untrue.** A specific false answer reaches Supported, like a false line in a profile. That's the decision you made, and the label stays visible.
- **The rules still need the requirement's wording.** "Drew blood from 30 patients" doesn't show phlebotomy, though the answer is saved. The page says the rules look for the requirement's own words, so someone may reword it, and that's easy to game by parroting.
- **Answers appear on the analysis page only**, not under the role in Experience. They count for every job, and are listed on every job's analysis page.
- **Removing an answer** doesn't re-run the analysis. The page marks the analysis out of date.
